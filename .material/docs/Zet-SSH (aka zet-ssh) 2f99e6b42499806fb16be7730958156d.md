# Zet-SSH (aka zet-ssh)

**Tagline:** A modern, open-source SSH workspace: profiles + encrypted vault + tabs + file browser + tunnels + command library — with transparent, copyable commands.

## 1) What Zet-SSH is

Zet-SSH is a cross-platform terminal app and SSH manager built in Go that turns “SSH into servers” into a clean, repeatable workflow.

It combines:

- A **terminal** for interactive SSH sessions
- A **profile manager** (named connections)
- A **secure local vault** (encrypted storage for credentials/keys/secrets)
- A **remote file browser** + transfer
- A **tunnel builder** (local↔remote port forwards) with a visible “command log”
- A **command library** (snippets, aliases, autofill)

Everything is designed to be **learnable** and **auditable**: every action shows the exact SSH/SCP/SFTP command (or library call) behind it.

---

## 2) Target users

- Devs who juggle many servers (VPS, edge nodes, etc.)
- DevOps/SRE: frequent SSH + tunnels + file moves
- Students/learners: want a “what command did this run?” UI
- Teams that want **consistent** connection profiles and shared snippets (optional)

Non-goals (at least for v1):

- Full IDE features
- Full-blown remote desktop
- Replacing tools like Ansible; Zet-SSH focuses on interactive operations and quick workflows

---

## 3) Core product principles

1. **Vault-first:** nothing sensitive stored in plaintext.
2. **Fast connect:** connect in 1–2 clicks.
3. **Everything is copyable:** show generated commands and logs.
4. **Keyboard-first:** power-user shortcuts everywhere.
5. **Tabs + workspace:** multiple sessions like a browser.
6. **Offline-friendly:** profiles, vault, snippets live locally.

## 4) Key features

### 4.1 SSH Profiles (Saved Connections)

**What:** Save a connection once, reuse forever.

**Profile fields**

- Name (e.g., `prod-api`, `camera-node-01`)
- Host/IP
- Port (default 22)
- Username
- Auth method:
    - SSH agent
    - Private key (path or imported into vault)
    - Password (stored encrypted)
- Optional:
    - Jump host (ProxyJump)
    - Known-hosts behavior (strict / prompt / accept)
    - Keepalive interval
    - Preferred cipher/KEX options (advanced)
    - Default remote working directory
    - Tags (prod/dev/cameras)

**UX behavior**

- When a user pastes an SSH command, Zet-SSH offers: **“Save as Profile?”** and parses:
    - `user@host`, `p`, `i`, `ProxyJump`, etc.

### 4.2 Encrypted Vault (Local)

**What:** Secure store for:

- Passwords
- Private keys (optional import)
- Per-profile secrets
- Snippet variables (like `${DB_PASS}`)

**Requirements**

- Cross-platform encryption
- Fast unlock
- Auto-lock timer

**Design**

- Vault is a single encrypted file: `vault.zet`
- Key derivation from a master password:
    - Argon2id recommended
- Encryption: XChaCha20-Poly1305 (or AES-GCM if needed)
- Optional: integrate OS keychain (Windows Credential Manager / macOS Keychain / libsecret) to store the vault key so users can unlock with a click.

### 4.3 Terminal Sessions (Tabs + Sidebar)

**What:** Multiple concurrent sessions.

**UI**

- Zen-browser style **auto-hidden sidebar** for tabs
- Tabs can be pinned, grouped, renamed

### 4.4 Remote File Browser + Transfer

**What:** Click a button in a session to open a file browser.

Capabilities

- List directories, navigate, breadcrumbs
- Download/upload
- Drag & drop (desktop)
- Resume transfers (v2)
- Basic file ops: rename, delete, mkdir
- Display permissions, size, modified time

Implementation

- Prefer **SFTP** via Go library over calling `scp`.
- Use streaming transfers with progress.

### 4.5 Tunnel Builder (Port Forwarding)

**What:** Create tunnels visually, but always show the actual SSH command.

Tunnel types

- Local forward: `L localPort:destHost:destPort`
- Remote forward: `R remotePort:destHost:destPort`
- SOCKS proxy: `D localPort`

UX

- UI form to choose type and values
- “Test port” helper
- “Copy command” button
- “Run tunnel” button
- Tunnels can be saved per profile

Implementation

- Either spawn `ssh` binary with flags OR implement forwarding via `x/crypto/ssh`.
- v1 recommendation: implement via Go for portability + control.

### 4.6 Command Library (Snippets, Aliases, Autofill)

**What:** Save common commands and reuse quickly.

Features

- Snippets scoped to:
    - Global
    - Profile
    - Tag group
- Aliases: type `deploy` → expands to a full command
- Variables:
    - `${HOST}` `${USER}` `${PWD}`
    - Vault variables `${SECRET:db_pass}`
    - Prompt variables `${ASK:project}`
- Smart suggestions:
    - Based on shell history per profile
    - Based on frequently used snippets

Safety

- “Redact secrets” in logs by default

### 4.7 Transparent Debug Console (Command Log)

**What:** A bottom panel that shows “what Zet-SSH executed”.

Shows

- Generated SSH config
- Tunnel commands
- SFTP ops (human-readable)
- Connection events

Includes

- Copy button
- Export logs
- Toggle “redact sensitive”

## 6) Architecture (Go)

### 6.1 High-level components

1. **UI App** (desktop)
2. **Core** (profiles, vault, commands, workspace)
3. **SSH Engine** (connect, shell, tunnels)
4. **SFTP Engine** (file browser, transfer)
5. **Logging/Telemetry** (local only by default)

### 6.2 Recommended desktop stack

Pick one:

- **Fyne**: pure Go UI (simpler, but  advanced).

### 6.3 Core packages (suggested)

- `internal/vault` encryption + key derivation
- `internal/profiles` CRUD + parsing ssh command
- `internal/sshx` SSH session + PTY + tunnel
- `internal/sftp` directory listing + transfers
- `internal/snips` snippet engine + variables
- `internal/workspace` tabs + state persistence
- `internal/logx` command log + redaction
- `internal/osx` keychain + notifications

### 6.4 Data formats

All local. Suggested files:

- `profiles.json` (non-sensitive only)
- `vault.zet` (encrypted)
- `workspaces.json`
- `snippets.json`

Sensitive material must never be in `profiles.json`.

## 7) Data model

### 7.1 Profile

- `id` (uuid)
- `name`
- `host`
- `port`
- `user`
- `authType`: agent | key | password
- `keyRef` (vault ref) or key path
- `passwordRef` (vault ref)
- `proxyJump` (optional)
- `tags[]`
- `defaults`: cwd, env vars, shell
- `createdAt`, `updatedAt`, `lastConnectedAt`

### 7.2 Vault item

- `id`
- `type`: password | privateKey | secret
- `name`
- `encryptedBlob`
- `metadata` (createdAt, lastUsedAt)

### 7.3 Snippet

- `id`, `name`, `command`, `scope`, `tags[]`
- `variables[]` (optional)

### 7.4 Tunnel definition

- `id`, `name`, `type` (L/R/D)
- `localPort`, `remotePort`, `destHost`, `destPort`
- `bindAddress` (127.0.0.1 default)

## 8) Security design

- Default to **strict host key checking**.
- Vault encryption with strong KDF.
- Redaction of secrets in logs.
- Auto-lock vault on idle.
- Never store plaintext passwords on disk.
- Optional: require re-unlock when exporting/copying secrets.

Threats and mitigations

- Stolen laptop: vault encrypted + auto-lock + OS keychain optional
- MITM: strict host key checking, known-hosts manager
- Shoulder surfing: hide secrets, redact logs

## 11) CLI companion

A small CLI `zet` that:

- lists profiles
- opens a connection in the Zet-SSH UI
- creates tunnels from terminal
- imports SSH config

Example:

- `zet connect prod-api`
- `zet tunnel prod-api -L 5433:127.0.0.1:5432`
